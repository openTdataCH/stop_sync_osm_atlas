# Stop Sync: ATLAS ↔ OSM

This project provides a systematic pipeline to identify, analyze, and resolve discrepancies between public transport stop data from **ATLAS** (Swiss official data) and **OpenStreetMap (OSM)**.

## Purpose

Switzerland has two valuable sources of public transport data:

- **ATLAS**: The authoritative dataset from the Swiss Federal Office of Transport, containing official traffic points, platform designations, and timetable associations.
- **OpenStreetMap (OSM)**: A community-maintained, freely available geographic database with rich attribute data.

By systematically comparing these datasets, we can:

**Improve data quality and detect anomalies for both datasets** by identifying missing stops, incorrect locations, or outdated attributes.

## System Workflow

The system is designed to re-import base data periodically (e.g., weekly) to stay synchronized with ATLAS and OSM updates. The Import DB is fully rebuilt on each run, while the User Input DB (auth data, user notes) is kept separate and never wiped.


```mermaid
flowchart LR
    subgraph Sources["Data Sources"]
        A[("ATLAS<br/>Official Swiss Data")]
        O[("OSM<br/>Transport Data")]
    end

    subgraph Pipeline["Processing Pipeline"]
        direction TB
        D["1. Download & Process"]
        M["2. Multi-Stage Matching"]
        P["3. Problem Detection"]
        I["4. Database Import"]
        D --> M --> P --> I
    end

    subgraph Output["Output"]
        IDB[("Import DB<br/>PostgreSQL + PostGIS")]
        UIB[("User Input DB<br/>PostgreSQL")]
        W["Web Application"]
        IDB --> W
        UIB --> W
    end

    A --> D
    O --> D
    I --> IDB
    W -->|"User notes &amp; auth"| UIB
```

**Import DB** is wiped and rebuilt on every pipeline run. **User Input DB** persists across runs — it stores auth data and user notes. Solution persistence (feeding user corrections back into the pipeline) is modelled but not yet active. See [4. Databases](4.%20Databases.md) for details.
