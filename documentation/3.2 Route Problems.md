# Route Problems

> [!WARNING]
> **Route problems are not yet implemented.** This document defines the conceptual framework for future implementation. The definitions are based on existing data structures but detection logic has not been built. This is just a draft. Current data strucutres might change a lot.

Route problems identify **route-level inconsistencies** between ATLAS and OSM datasets. Unlike [Stop Problems](3.1%20Stop%20Problems.md) which focus on individual stops, route problems examine:

1. **Stop-Route Associations**: Whether matched stops serve the same routes in both datasets
2. **Route-Route Consistency**: Whether entire routes exist in both datasets with matching stop sequences

## Conceptual Framework

Route problems are **complementary** to stop problems:
- A **stop problem** indicates an issue with a single stop (location, attributes, matching)
- A **route problem** indicates an issue with route data (missing routes, wrong associations, sequence errors)

Both types of problems can exist simultaneously. For example, a stop might be correctly matched (no stop problem) but serve different routes in each dataset (route problem).

---

## 1. Stop-Route Association Problems

Problems where a **matched stop pair** has inconsistent route associations between ATLAS and OSM.

### Problem Types

#### 1.1 Route Missing in OSM

**Definition**: ATLAS shows a stop serves route X, but OSM has no corresponding route relation.

**Detection Method**:
1. For each route in `atlas_stops.routes_unified`
2. Check if a semantically equivalent route exists in `osm_nodes.routes_osm`
3. Use semantic equivalence criteria (see below)


**Example**:  ATLAS shows "Zürich HB" serves S3, but the OSM node has no route relation for S3 (hypotetical).

---

#### 1.2 Route Missing in ATLAS

**Definition**: OSM shows a stop is member of route Y, but ATLAS has no corresponding route data.

**Detection Method**:
1. For each route in `osm_nodes.routes_osm`
2. Check if a semantically equivalent route exists in `atlas_stops.routes_unified`
3. Use semantic equivalence criteria (see below)


**Example**: OSM shows a bus stop is member of route "Bus 31", but ATLAS has no route data for that stop → **P2 or P3 problem** depending on operator

---

#### 1.3 Direction Mismatch

**Definition**: Both datasets show the route, but with different or conflicting direction information.

**Detection Method**:
1. Find semantically equivalent routes in both datasets
2. Compare direction fields:
   - ATLAS: `direction_id`, `direction_name`, `direction_uic`
   - OSM: `from`, `to` tags in route relation
3. Flag if directions are contradictory (e.g., opposite directions)

**Priority Criteria**:

| Priority | Condition | Rationale |
|----------|-----------|-----------|
| **P1** | Opposite directions (e.g., ATLAS says "towards A", OSM says "towards B") | Significant data inconsistency |
| **P2** | Missing direction in one dataset | Minor issue, direction may be implicit |

**Example**: ATLAS shows "S3 towards Zurich", OSM shows "S3 towards Lausanne" for the same bus stop. There's probably another matched pair with the same UIC number that has the oposite situation.
---

### Semantic Equivalence Criteria

Two routes are considered "semantically equivalent" if **any** of the following match:

| Criterion | ATLAS Field | OSM Field | Matching Rule |
|-----------|-------------|-----------|---------------|
| **GTFS Route ID** | `route_id` or `route_id_normalized` | `gtfs:route_id` tag | Exact match (case-insensitive) |
| **HRDF Line Name** | `line_name` | `ref` tag | Exact match after normalization* |
| **Route Name** | `route_name_short` or `route_name_long` | `name` tag | Fuzzy match** |

\* **Normalization**: Remove whitespace, hyphens, and convert to uppercase (e.g., "S 3" = "S-3" = "S3")

## 2. Route-Route Consistency Problems

Problems where an entire route exists in one dataset but not the other, or exists in both with different stop sequences.

### Data Sources

The `routes_and_directions` table aggregates route data from both datasets:

| Column | Description | Populated From |
|--------|-------------|----------------|
| `atlas_route_id` | GTFS route ID | `atlas_routes_unified.csv` |
| `atlas_sloids_json` | JSONB array of sloids on this route | Aggregated during import |
| `osm_route_id` | OSM route relation ID | `osm_nodes_with_routes.csv` |
| `osm_nodes_json` | JSONB array of OSM node IDs on this route | Aggregated during import |
| `match_type` | How ATLAS/OSM routes were matched | Computed during import |

See [4.1 Stops DB](4.1%20Stops%20DB.md#table-routes_and_directions) for complete schema.

### Problem Types

#### 2.1 Route Exists Only in ATLAS

**Definition**: A route appears in GTFS/HRDF but has no corresponding OSM route relation.


**Priority Criteria**:

| Priority | Condition |
|----------|-----------|
| **P1** | Routes with >20 stops |
| **P2** | Routes with 5-20 stops |
| **P3** | Routes with <5 stops |

**Example**: GTFS shows "Bus 72" with 25 stops, but no OSM route relation exists → **P1 problem**

---

#### 2.2 Route Exists Only in OSM

**Definition**: An OSM route relation exists but has no corresponding ATLAS route.

---

#### 2.3 Stop Sequence Mismatch

**Definition**: Route exists in both datasets but with different stops or stop order.

**Detection Method**:
1. Find matched routes (same `atlas_route_id` and `osm_route_id`)
2. Compare `atlas_sloids_json` vs `osm_nodes_json`
3. Calculate percentage of stops that differ (accounting for matched pairs)

**Priority Criteria**:

| Priority | Condition | Rationale |
|----------|-----------|-----------|
| **P1** | >40% of stops differ | Likely different routes with same name |
| **P2** | 10-40% differ | Significant discrepancy |
| **P3** | <10% differ | Minor differences (e.g., seasonal stops) |

**Example**: GTFS route "S3" has 20 stops, OSM route "S3" has 10 matching stops + 10 different → **P1 problem** (50% differ)

---

#### 2.4 Route Attributes Mismatch

**Definition**: Route exists in both datasets but has different metadata (name, operator, type).

**Detection Method**:
1. Find matched routes
2. Compare:
   - `route_name` / `route_short_name` / `route_long_name`
   - `route_type` (GTFS) vs `route` tag (OSM)
   - Operator fields
