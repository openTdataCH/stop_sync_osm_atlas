## The Goal
The raw ATLAS data gives us the physical location of stops (platforms), but it doesn't tell us **what** stops there. To perform matching with OpenStreetMap, we can use:
- Which lines serve a platform (e.g., "Tram 11", "S12").
- The direction of travel (e.g., "towards Rehalp").

## Orchestration
The creation of this unified file is orchestrated by the main script `matching_and_import_db/downloader/get_atlas_data.py`. This script:
1.  Downloads the raw ATLAS data.
2.  Calls the **GTFS** and **HRDF** processing modules to extract route information in memory.
3.  Merges the results and writes them directly to the output CSV using the `write_unified_routes_csv_direct()` function.

## The Unified Output
The processing output is a single unified file: `data/processed/atlas_routes_unified.csv`.

Each row in this file represents a unique **(stop, route, direction)** combination.

> **Note on Terminology**: This file establishes **Route-to-Stop associations** (enriching ATLAS stops with route info). This is distinct from the **Stop-to-Stop matching** (ATLAS to OSM).  [2.4 Route Matching](2.4%20Route%20Matching.md) uses this data to find Stop-to-Stop matches.

The file contains the following columns:
- **`sloid`**: The ATLAS identifier for the specific platform.
- **`source`**: The data source (`gtfs` or `hrdf`).
- **`route_id` / `route_id_normalized`**: GTFS identifiers for the route.
- **`route_name_short` / `route_name_long`**: GTFS route names (e.g., "11", "S3").
- **`line_name`**: HRDF line name.
- **`direction_id`**: GTFS direction identifier (usually 0 or 1).
- **`direction_name`**: The destination or direction string (e.g., "Rehalp").
- **`direction_uic`**: The UIC identifier of the destination station.
- **`evidence`**: Internal metadata indicating the method used to associate the route/direction with the ATLAS stop (e.g., `gtfs_first_last`, `hrdf_fplan`). This refers to the derivation of route data, *not* the final ATLAS-to-OSM matching.
- **`as_of`**: The date the data was processed.

This unified dataset allows the matching algorithm to work agnostically, without worrying about where the route data came from.
