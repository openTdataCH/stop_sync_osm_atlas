# 5.2 Statistics and Timestamps

Engine result bundles include domain diagnostics, run summary, matching quality metrics, input fingerprints, profile configuration and source timestamps. The app consumes these records and prepares report summaries using its own database and presentation services.

`backend/importing/importer.py` projects exported values and refreshes `data/stats.json`; it never recalculates spatial matching quality or reads route/source CSVs. Optional Swiss GTFS identity and ATLAS filtering statistics travel as result extensions. `dataset_publication.manifest` records the active run transactionally even if a later presentation-file write fails.

The engine records UTC timestamps. The app's current Swiss display uses `backend/services/time_utils.py`; presentation timezone is distinct from matching behavior. The scheduler records completion in the shared status store and `data/data_meta.json`.

Quality summaries are computed in `engine/src/transport_matcher/statistics.py`. Query-based problem/route counts and PDF presentation remain in `backend/services/stats_export.py`. PDFs are generated from these exported summaries and the active app database.

See [result publication](5.1%20Import%20Process.md) and [the public result format](../engine/RESULT_FORMAT.md).
