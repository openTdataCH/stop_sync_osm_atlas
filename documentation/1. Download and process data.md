# Download and process data

This chapter explains how we prepare the datasets that power the matching pipeline. Before any OSM ↔ ATLAS matching happens, we download the data inputs, apply filters, and produce CSVs files used by downstream steps.


### At a glance

| Input | Source | Key filters | Primary outputs |
| --- | --- | --- | --- |
| ATLAS traffic points (stops) | `https://data.opentransportdata.swiss/en/dataset/traffic-points-actual-date/permalink` | <ul><li>UIC prefix == '88'</li><li>Inside precise CH polygon</li><li>validTo in the future</li><li><code>trafficPointElementType == BOARDING_PLATFORM</code></li></ul> | `data/raw/stops_ATLAS.csv` |
| GTFS (timetable data) | `https://data.opentransportdata.swiss/de/dataset/timetable-2025-gtfs2020/permalink` | <ul><li>Swiss stops only (<code>stop_id</code> prefix 85 + inside CH polygon)</li><li>Streaming two-pass over <code>stop_times.txt</code> to build unique <code>(stop_id, route_id, direction_id)</code></li></ul> | Integrated in-memory; unified with HRDF to `data/processed/atlas_routes_unified.csv` |
| HRDF (timetable data) | See Cookbook: `https://opentransportdata.swiss/en/cookbook/timetable-cookbook/hafas-rohdaten-format-hrdf/` | <ul><li>Parse only <code>GLEISE_LV95</code>, <code>FPLAN</code>, <code>BAHNHOF</code></li><li>Two-pass on <code>GLEISE_LV95</code> to target only needed sloids</li></ul> | Direction tuples per sloid; unified to `data/processed/atlas_routes_unified.csv` |
| OSM (nodes + routes) | Overpass API `http://overpass-api.de/api/interpreter` | <ul><li>Switzerland area</li><li>PT nodes (<code>public_transport</code>, <code>highway=bus_stop</code>, etc.)</li><li>Include route relations referencing them</li></ul> | `data/raw/osm_data.xml`, `data/processed/osm_nodes_with_routes.csv`, `data/processed/osm_routes_with_nodes.csv` |
