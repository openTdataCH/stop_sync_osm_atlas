### GTFS ATLAS data

### Public view
GTFS is a common timetable format. We use it to learn which routes and directions serve each Swiss stop, then map those GTFS stops to ATLAS `sloid` identifiers. To keep things fast and memory-safe, we process the huge `stop_times.txt` in two streaming passes.

What we do:
- Load Swiss stops from GTFS (`stop_id` starts with `85`) and ensure they are inside Switzerland’s precise border
- Pass 1 (streaming): collect relevant `trip_id` and first/last Swiss stop per trip → a representative direction string per route
- Load only the referenced `trips` and `routes`
- Pass 2 (streaming): build unique `(stop_id, route_id, direction_id)` triples
- Map `stop_id → sloid` using a strict rule with two careful fallbacks

What it enables:
- A compact, reproducible per-stop set of routes and a human-readable direction per route, aligned to ATLAS stops

Diagram (two-pass streaming over stop_times):
```
stops.txt ──► filter to CH (85 prefix + polygon) ──► Swiss stops set
                                         │
                                         ▼
stop_times.txt (pass 1, streaming) ──► relevant trip_ids
                                         │            ┌──────────┐
                                         ├───────────►│ trips.txt │ (filter to relevant trips)
                                         │            └──────────┘
                                         │                    │
                                         ▼                    ▼
 derive first/last Swiss stop per trip  route_directions   routes.txt (referenced only)
                                         │                    │
                                         ▼                    ▼
stop_times.txt (pass 2, streaming) ──► unique (stop_id, route_id, direction_id)
                                         │
                                         ▼
map stop_id → sloid (strict + fallbacks) ──► integrated per-stop routes/direction
```
