# 4.2 Route Entity Problems

> [!NOTE]
> Route entity problems are **partially implemented** during route import. The current code only detects route metadata mismatches for already matched route pairs; unmatched-route detection is still planned.

Route Entity problems identify inconsistencies at the **Route object** level. These problems concern the existence and global properties of a route, independent of its individual stops.

**Key Question:** *"Does this route exist and is it defined correctly?"*

## 4.2.1 Unmatched Route (Planned)

**Definition**: A route exists in one dataset but has no corresponding route in the other.

*   **ATLAS-only**: Route appears in GTFS but has no corresponding OSM route relation.
*   **OSM-only**: An OSM route relation exists but has no corresponding ATLAS route.

**Priority Criteria**:

| Priority | Condition |
|----------|-----------|
| **P1** | Routes with >20 stops |
| **P2** | Routes with 5-20 stops |
| **P3** | Routes with <5 stops |

**Example**: GTFS shows "Bus 72" with 25 stops, but no OSM route relation exists. This is a global issue; the route is missing entirely.

## 4.2.2 Route Metadata Mismatch (Implemented)

**Definition**: A route exists in both datasets (matched pair), but their global attributes conflict.

**Detection Method**:
1. Identify matched routes from `routes_matched` (route-level linkage output).
2. Compare the currently implemented fields:
   *   ATLAS `route_short_name` against OSM `ref` / `name`
   *   GTFS `route_type` against the OSM `route` mode

**Implementation Note**:
- This check runs in `matching_and_import_db/problem_detection/route_predicates/route_problems.py` during route payload preparation.
- It emits `route_metadata_mismatch` with priority `1` for mode mismatches and priority `2` for name/ref mismatches.
- Broader metadata comparisons such as `network` / `operator` are not implemented yet.
