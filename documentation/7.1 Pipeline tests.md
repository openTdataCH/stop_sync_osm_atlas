# 7.1 Pipeline Tests

Because running the full ATLAS and OSM data synchronization pipeline takes significant time and memory, having an end-to-end integration test that operates on a minuscule, deterministic dataset is extremely valuable for validating the core architecture rapidly.

## The Small Pipeline Test

The primary test for continuous integration of the matching engine is **the small pipeline test**. It executes the entire lifecycle (heuristics over memory states $\rightarrow$ problem detection $\rightarrow$ database insertion) on a tiny fraction of the data. 

### What it does

Located at `tests/matching_pipeline/test_small_pipeline.py`, this test performs the following sequence:

1. **Environment Override:** Modifies the `$ATLAS_STOPS_CSV` and `$OSM_XML_FILE` environment variables to point toward `tests/data/sample_atlas.csv` and `tests/data/sample_osm.xml`.
2. **Setup In-Memory Database:** Relies on the Docker Pytest command setting the environmental variable `DATABASE_URI=sqlite://` so that SQLAlchemy operates entirely in memory, wiping and building the normalized schema instantly. 
3. **Execute Pipeline:** Triggers the pipeline via `run_matching()` from `orchestrator.py`, running all constraints, distance calculations, and predicates sequentially on the mock data.
4. **Hydrate DB:** Triggers `import_to_database()` from `importer.py` to seamlessly execute Phase 1, Phase 2, and Phase 3 of database insertion rules, proving that the models translate into SQLAlchemy flawlessly.
5. **Validation:** Asserts that:
   - Matches are successfully generated (at least 50% match rate amongst the 40 randomly sampled test nodes, verifying the data logic works).
   - `AtlasStop`, `OsmNode`, and `StopsMatched` entries populate the database automatically. 

### Why the Sample Data Works

The sample dataset consists of around ~40 ATLAS nodes and ~150 OSM nodes. Because it was carefully parsed to maintain spatial and property logic between nodes, the dataset natively generates a ~100% matched-sloid rate, guaranteeing that we aren't testing negative failures.

If the match percentage in the test ever drops beneath 50%, the pipeline logic (specifically distances or predicates) has suffered a major regression. 

## Running the Small Pipeline Test Local / VSCode

There is a dedicated VSCode Command configured so that you can run it directly:
- **VSCode Task:** `Docker: Run Small Pipeline Test`

Alternatively, you can trigger it via the command line inside the project root:

```bash
docker compose run --rm --no-deps --entrypoint '' \
  -e DATABASE_URI=sqlite:// \
  -e USER_INPUT_DATABASE_URI=sqlite:// \
  app python -m pytest tests/matching_pipeline/test_small_pipeline.py -v
```
