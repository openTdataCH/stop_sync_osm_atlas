# CI (GitHub Actions) and Tests

This repository uses **GitHub Actions** for continuous integration (CI). The CI pipeline runs JavaScript tests, Python linting, and Python unit tests on every push and pull request.

## Overview

| Job | What it does | Blocks merge? |
|-----|--------------|---------------|
| `javascript-tests` | Runs Jest tests, uploads coverage | ✅ Yes |
| `python-lint` | Runs flake8 (blocking), black/isort (advisory) | ⚠️ flake8 only |
| `python-tests` | Runs pytest, uploads coverage | ✅ Yes |

## Workflow Location

```
.github/workflows/tests.yml
```

## When CI Runs

The workflow triggers on:

- `push` to `main`, `master`, or `develop`
- `pull_request` targeting `main`, `master`, or `develop`

## Test Structure

```
stop_sync_osm_atlas/
├── static/js/tests/           # JavaScript tests (Jest)
│   ├── setup.js               # Global mocks (Leaflet, jQuery)
│   └── *.test.js              # Test files
├── tests/                     # Python tests (pytest)
│   ├── conftest.py            # Shared fixtures
│   ├── test_matching.py       # Matching pipeline tests
│   └── test_backend.py        # Backend API tests
└── .github/workflows/
    └── tests.yml              # CI workflow definition
```

## Coverage

Both test suites generate coverage reports:

| Suite | Artifact Name | Location |
|-------|---------------|----------|
| JavaScript | `js-coverage-report` | `coverage/` |
| Python | `python-coverage-report` | `htmlcov/` |

Coverage artifacts are available for download from the GitHub Actions run page.

## Quick Reference

### Run All Tests Locally (Using Docker - Recommended)

To ensure you have the **exact same dependencies** as GitHub Actions, run tests inside your Docker container:

```bash
./run-tests-local.sh
```

This script runs all three test suites (JavaScript, Python lint, Python tests) using the same environment as CI/CD.

**Run individual test suites:**

```bash
# JavaScript tests only
docker-compose run --rm app-dev bash -c "npm ci && npm test -- --coverage --ci"

# Python lint only
docker-compose run --rm app-dev bash -c "pip install flake8 black isort && flake8 . && black --check . && isort --check-only ."

# Python tests only
docker-compose run --rm app-dev bash -c "pip install pytest pytest-cov && FLASK_ENV=testing TESTING=true DATABASE_URI='sqlite:///:memory:' AUTH_DATABASE_URI='sqlite:///:memory:' SECRET_KEY='test-secret-key' pytest tests/ --cov=matching_process --cov=backend -v"
```

### Run Tests Directly on Your Machine (Not Recommended)

If you have the exact same Python/Node versions as CI, you can run tests directly:

```bash
# JavaScript
npm ci
npm test

# Python
pip install -r requirements.txt
pip install pytest pytest-cov
pytest tests/ -v
```

⚠️ **Note:** Running tests directly on your machine may give different results than CI if your environment differs. Use the Docker-based approach above for consistent results.

### Run with Coverage

```bash
# JavaScript
npm run test:coverage

# Python
pytest tests/ --cov=matching_process --cov=backend --cov-report=html -v
```

## Notes on Dependency Management

This repo maintains **two separate dependency ecosystems**:

| Ecosystem | Manager | Lock File | Purpose |
|-----------|---------|-----------|---------|
| Python | pip | `requirements.txt` | Backend, matching pipeline, data processing |
| JavaScript | npm | `package-lock.json` | Frontend tests (Jest) |

CI uses `npm ci` for JavaScript (reproducible installs from lockfile) and `pip install -r requirements.txt` for Python.
