# CI (GitHub Actions) and Tests

This repository uses **GitHub Actions** for continuous integration (CI). The current workflow runs documentation link checks, JavaScript tests, Python linting, and Python tests on every push and pull request.

## Overview

| Job | What it does | Blocks merge? |
|-----|--------------|---------------|
| `documentation-links` | Verifies markdown links in `documentation/` and rendered `/docs` pages | Yes |
| `javascript-tests` | Runs Jest tests, uploads coverage | Yes |
| `python-lint` | Runs flake8 (blocking), black/isort (advisory) | flake8 only |
| `python-tests` | Runs pytest, uploads coverage | Yes |

## Workflow Location

```
.github/workflows/tests.yml
```

## When CI Runs

The workflow triggers on:

- `push` to `main`, `master`, or `develop`
- `pull_request` targeting `main`, `master`, or `develop`

## Coverage

| Suite | Artifact Name | Location |

| JavaScript | `js-coverage-report` | `coverage/` |
| Python | `python-coverage-report` | `htmlcov/` |

Coverage artifacts are available for download from the GitHub Actions run page.

## Run Tests Locally

To keep local runs close to CI, use the same commands manually.

**Run individual test suites:**

```bash
# Matching pipeline tests
docker compose run --rm --no-deps --entrypoint '' \
    -e DATABASE_URI=sqlite:// \
    -e USER_INPUT_DATABASE_URI=sqlite:// \
    scheduler python -m pytest tests/matching_pipeline/ -v

# Documentation link tests
docker compose run --rm --no-deps --entrypoint '' \
    -e DATABASE_URI=sqlite:// \
    -e USER_INPUT_DATABASE_URI=sqlite:// \
    scheduler python -m pytest tests/test_docs_links.py -v

# JavaScript tests (host)
npm ci
npm test -- --coverage --ci
```

Optional JavaScript run in a throwaway container:

```bash
docker run --rm -v "$PWD":/work -w /work node:20 \
  sh -lc "npm ci && npm test -- --coverage --ci"
```

> [!WARNING]
> **Known limitation in current Docker setup:** the `app` image is intentionally lightweight and does not include heavy pipeline dependencies (for example `pandas`) or Node.js. Commands like `docker compose run app python -m pytest tests/matching_pipeline/...` and `docker compose run app npm test` can fail for that reason.

### Run with Coverage

```bash
# JavaScript
npm run test:coverage

# Python
pytest tests/ --cov=matching_process --cov=backend --cov-report=html -v
```

The Python coverage command above matches the current GitHub Actions workflow verbatim. The package selector appears stale, but the documentation records the workflow as it exists today.

## Notes on Dependency Management

This repo maintains **two separate dependency ecosystems**:

| Ecosystem | Manager | Lock File | Purpose |
|-----------|---------|-----------|---------|
| Python | pip | `requirements-*.txt` | Backend, matching pipeline, data processing |
| JavaScript | npm | `package-lock.json` | Frontend tests (Jest) |

CI uses `npm ci` for JavaScript (reproducible installs from `package-lock.json`) and `pip install -r requirements-base.txt` (etc.) for Python.

For runtime containers, Python dependencies are split further into `requirements-base.txt`, `requirements-web.txt`, and `requirements-scheduler.txt` to keep the web image lightweight.
