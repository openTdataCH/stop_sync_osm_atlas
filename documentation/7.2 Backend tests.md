# 7.2 Backend tests

There is currently **no dedicated `tests/backend/` suite** in the repository. Backend coverage exists today in two narrower forms:

1. `tests/test_docs_links.py`
	- validates documentation routes and rendered internal links through the Flask app
2. `tests/matching_pipeline/test_validators.py`
	- covers backend validation and sanitization helpers such as pagination, text limits, and HTML sanitization

This means the backend still lacks broad endpoint-level regression coverage for blueprints such as `/api/data`, `/api/search`, `/api/problems`, and `/api/reports`.

## Current backend-adjacent coverage

| File | What it covers |
|------|----------------|
| `tests/test_docs_links.py` | Flask app bootstrapping plus `/docs` rendering and internal-link reachability |
| `tests/matching_pipeline/test_validators.py` | `backend.services.validators` helper behavior |

## Running the current checks

```bash
docker compose run --rm --no-deps --entrypoint '' \
  -e DATABASE_URI=sqlite:// \
  -e USER_INPUT_DATABASE_URI=sqlite:// \
  app python -m pytest tests/test_docs_links.py tests/matching_pipeline/test_validators.py -v
```

## Gap to keep in mind

The absence of a dedicated backend API suite means route behavior is still verified mostly indirectly: through documentation rendering tests, validator unit tests, manual use of the web app, and the importer-driven end-to-end tests.
